## Why v1.0

The early previews proved the point: free learning materials and practical quickstarts can help nonprofits question the rental trap before signing another contract. Leasehold wants your organisation locked in the cloud mine. The playbook is familiar: make a tool indispensable, change the terms, then make the exit hurt.

Salesforce's announced NPSP transition is one example of a platform change that can force a nonprofit to weigh a new migration. We name vendors because teams deserve to ask hard questions before committing. We do not claim every vendor is bad or that every organisation should self-host. We show the trade-offs, costs, and skills so you can choose with your eyes open.

An old office PC can be a useful test lab, but its age and RAM do not guarantee it can run a particular stack. Check each tool's requirements, backups, security updates, and maintenance load before putting real work on it. Own your tools by understanding them, not by pretending the work is free.

## Upgrade notes

If your organisation is considering a move away from a subscription:

1. Inventory the data, workflows, integrations, and contract terms you rely on.
2. Export and verify a backup before changing systems.
3. Pilot the replacement with test data and check its real operating costs.
4. Plan ownership, security updates, support, and a rollback path.
5. Cancel the old service only after the new system and its data have been validated.

Log off only when your mission is ready. Then build a stack you can keep.
